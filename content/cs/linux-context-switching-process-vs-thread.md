## 1. 컨텍스트 스위칭(Context Switching)이란?

<strong>컨텍스트 스위칭(Context Switching)</strong>이란 CPU가 현재 실행 중이던 작업의 상태(Context)를 메모리에 백업하고, 다음으로 실행할 작업의 상태를 읽어와 CPU에 교체해 넣는 과정을 말한다.

여기서 말하는 <strong>컨텍스트(Context)</strong>란 프로세스나 스레드가 현재 어디까지 실행되었는지를 나타내는 모든 상태 정보(CPU 레지스터 값, 프로그램 카운터, 스택 포인터, 메모리 매핑 정보 등)를 뜻한다.

### 책 읽기로 비유해 보면

두 권의 책(작업 A, 작업 B)을 번갈아 읽는 상황을 떠올려 보면 이해하기 쉽다.

1. 책 A를 읽다가 120페이지까지 읽은 위치에 **책갈피**를 꽂고 덮는다. (현재 Context 저장)
2. 책 B를 펼쳐 아까 꽂아둔 45페이지 책갈피 위치를 찾아 이어서 읽는다. (다음 Context 복원 및 실행)

이처럼 CPU도 하나의 코어에서 여러 작업을 번갈아 처리하기 위해, 실행 중이던 위치를 기록해 두고 다음 작업의 위치를 불러오는 과정을 반복한다.

## 2. 컨텍스트 스위칭은 왜 필요하고, 언제 발생할까?

### 필요한 이유

- **동시성(Concurrency) 제공**: 제한된 CPU 코어 위에서 여러 프로세스와 스레드가 동시에 실행되는 것처럼 동작하게 만들기 위함이다.
- **공정한 CPU 시간 분배**: 특정 작업이 CPU를 독점하지 않고 여러 작업이 공정하게 시간을 나눠 가질 수 있도록 한다.
- **우선순위 처리**: 긴급하거나 높은 우선순위를 가진 작업이 들어왔을 때 즉시 CPU를 할당해 빠르게 처리할 수 있다.

### 발생하는 시점

- **타임 슬라이스(Time Slice / Quantum) 소진**: 할당된 CPU 사용 시간을 모두 썼을 때
- **I/O 작업 및 리소스 대기**: 디스크 읽기/쓰기, 네트워크 응답 대기, 락(Lock) 획득 대기 등으로 인해 당장 CPU를 쓸 수 없는 상태(Blocked/Waiting)가 되었을 때
- **더 높은 우선순위의 인터럽트 발생**: 우선순위가 더 높은 작업이 선점(Preemption)할 때

## 3. 프로세스 스위칭 vs 스레드 스위칭: 공통점과 차이점

컨텍스트 스위칭은 전환 대상에 따라 두 가지로 나뉜다.

1. **프로세스 컨텍스트 스위칭 (Process Context Switching)**: 서로 다른 프로세스 간의 전환
2. **스레드 컨텍스트 스위칭 (Thread Context Switching)**: 같은 프로세스 내부의 스레드들 간의 전환

### 공통점

1. **커널 모드(Kernel Mode)에서 실행된다**
   - 프로세스가 실행되다가 하드웨어나 시스템 리소스를 다뤄야 하는 순간이 오면, 프로세스가 직접 자원에 접근하지 않고 운영체제(커널)를 통해 접근한다.
   - 이때 제어권이 `프로세스(User Mode) -> 커널(Kernel Mode)`으로 넘어가며, 컨텍스트 스위칭 작업 자체도 커널 모드에서 수행된다.
2. **CPU 레지스터 상태를 교체한다**
   - 작업 1이 CPU에서 실행되는 동안 레지스터에는 연산 중간값, 프로그램 카운터(PC), 스택 포인터(SP) 등이 계속 갱신된다.
   - 작업 2로 전환할 때는 작업 1의 레지스터 상태들을 메모리에 저장하고, 작업 2가 마지막으로 멈췄던 레지스터 값들을 CPU에 다시 채워 넣는다.

### 결정적 차이점: 가상 메모리 주소 공간과 캐시/TLB 오버헤드

가장 큰 차이는 **메모리 주소 공간의 공유 여부**에 있다.

| 구분 | 프로세스 컨텍스트 스위칭 | 스레드 컨텍스트 스위칭 |
| :--- | :--- | :--- |
| **메모리 영역** | 프로세스마다 독립된 가상 메모리 공간(Code, Data, Heap)을 가짐 | 같은 프로세스 내 스레드들은 **Code, Data, Heap 영역을 공유**함 (Stack과 레지스터만 독립) |
| **가상 메모리 처리** | 새로운 프로세스의 페이지 테이블을 가리키도록 **MMU 설정(CR3 레지스터 등)을 교체**해야 함 | 같은 메모리 공간을 공유하므로 메모리 주소 체계 관련 처리를 할 필요가 없음 |
| **캐시 / TLB 영향** | 주소 공간이 바뀌므로 **CPU L1/L2 캐시와 TLB(Translation Lookaside Buffer)가 무효화(Flush)** 됨 | 기존 캐시와 TLB 데이터를 그대로 재사용할 수 있음 |
| **전환 비용(오버헤드)** | 매우 큼 | 상대적으로 훨씬 가볍고 빠름 |

프로세스 간 전환에서는 페이지 테이블 기준 레지스터(`CR3`)가 바뀌면서 그동안 모아둔 주소 변환 캐시(`TLB`)를 전부 비워야 한다. 직후에 새로운 프로세스가 메모리에 접근할 때마다 캐시 미스(Cache Miss)와 TLB 미스가 연쇄적으로 발생하므로, 스레드 전환에 비해 훨씬 큰 성능 오버헤드가 발생한다.

## 4. 컨텍스트 스위칭 5단계 동작 과정

실제 CPU 내부에서 컨텍스트 스위칭이 일어나는 흐름은 다음 5단계로 정리할 수 있다.

```text
[1. 인터럽트 / 시스템 콜 발생]
   타임 슬라이스 소진, I/O 요청, 우선순위 선점 등으로 현재 작업 중단
   │
   ▼
[2. 커널 모드(Kernel Mode)로 전환]
   CPU 권한이 사용자 모드에서 커널 모드로 진입
   │
   ▼
[3. 현재 상태(Context) 저장]
   실행 중이던 레지스터 값(PC, SP 등)과 상태를 PCB 또는 TCB에 백업
   │
   ▼
[4. 다음 실행할 대상의 상태 복원 (Dispatch)]
   다음 프로세스/스레드의 PCB 또는 TCB에서 저장된 레지스터 값을 CPU에 로드
   (※ 프로세스 전환 시 CR3 교체 및 TLB 무효화 함께 발생)
   │
   ▼
[5. 사용자 모드(User Mode) 복귀 및 실행 재개]
   복원된 프로그램 카운터(PC) 위치부터 새로운 작업 실행 이어감
```

1. **인터럽트(Interrupt) 또는 시스템 콜(System Call) 발생**: 타임 슬라이스 소진, 입출력(I/O) 요청, 더 높은 우선순위의 작업 등장 등으로 현재 실행을 멈춘다.
2. **커널 모드로 전환**: CPU가 사용자 모드(User Mode)에서 커널 모드(Kernel Mode)로 진입해 운영체제가 제어권을 넘겨받는다.
3. **현재 상태(Context) 저장**: 현재 실행 중이던 프로세스나 스레드의 레지스터 값(프로그램 카운터 `PC`, 스택 포인터 `SP` 등)과 상태 정보를 프로세스의 **PCB(Process Control Block)** 또는 스레드의 <strong>TCB(Thread Control Block)</strong>에 저장한다.
4. **다음 실행할 대상의 상태 복원**: 스케줄러가 선택한 다음 대상의 PCB/TCB를 읽어, 저장되어 있던 레지스터 값들을 CPU에 다시 로드(디스패치)한다. 다른 프로세스로 전환되는 경우 가상 메모리 매핑 정보(`CR3` 레지스터)도 함께 교체한다.
5. **사용자 모드 복귀 및 실행 재개**: 커널 모드에서 사용자 모드로 돌아온 뒤, 복원된 `PC` 지점부터 새로운 프로세스나 스레드의 실행을 이어간다.

---

## 5. 핵심 요약

- **컨텍스트 스위칭**은 CPU가 한 프로세스/스레드의 실행을 중단하고 다른 프로세스/스레드로 제어권을 넘기는 과정이다.
- 실행 중이던 레지스터 값, 프로그램 카운터(`PC`), 스택 포인터(`SP`)를 **PCB** 또는 **TCB**에 저장하고, 다음 작업의 상태를 CPU에 복원한다.
- 특히 **프로세스 간 전환**은 가상 메모리 매핑(`CR3` 레지스터)을 교체하면서 CPU의 **L1/L2 캐시와 TLB가 무효화**되므로, 메모리 공간을 공유하는 **스레드 전환보다 훨씬 큰 오버헤드**가 발생한다.
