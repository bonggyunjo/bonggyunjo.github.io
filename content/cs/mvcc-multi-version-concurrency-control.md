## 1. 등장 배경: 왜 2PL에서 MVCC로 넘어왔을까?

이전에 정리했던 글([트랜잭션 격리 수준(Isolation Level) 4단계와 3대 이상현상(Anomalies)의 원리](https://bonggyunjo.github.io/backend/transaction-isolation-levels-and-anomalies/))에서도 살펴보았듯, 데이터베이스 동시성 제어는 결국 다음 질문에서 출발한다.

> **"여러 작업을 동시에 처리해서 성능을 높이면서도, 마치 한 번에 하나씩 실행한 것처럼 데이터를 안전하게 지킬 수 있을까?"**

MVCC 이전에는 주로 **2단계 잠금(2PL, Two-Phase Locking)** 방식을 사용했다. 데이터를 읽는 동안에는 공유 락(`S-Lock`)을 걸어 수정을 막고, 수정하는 동안에는 배타 락(`X-Lock`)을 걸어 읽기조차 막는 방식이다. 하지만 이 구조에는 두 가지 뚜렷한 문제가 있었다.

1. **읽기-쓰기 간 충돌 문제**: 누군가 데이터를 수정하고 있으면, 단순히 값을 조회만 하려는 사용자도 쓰기 작업이 끝날 때까지 대기해야 했다.
2. **대기 병목 및 교착 상태(Deadlock) 문제**: 동시 접속자가 늘어날수록 잠금을 기다리는 병목 현상이 심해졌고, 트랜잭션들이 서로의 잠금이 풀리기를 기다리다 멈추는 교착 상태가 자주 발생했다.

이 한계를 풀기 위해 *"데이터를 바로 덮어쓰지 않고, 시간순으로 기록(버전)을 남겨두면 어떨까?"*라는 아이디어에서 출발한 개념이 바로 <strong>다중 버전 동시성 제어(MVCC)</strong>다.

## 2. 다중 버전 동시성 제어(MVCC)란?

<strong>MVCC(Multi-Version Concurrency Control)</strong>는 데이터베이스에서 여러 트랜잭션이 동시에 접근할 때, **데이터를 변경할 때 기존 값을 덮어쓰지 않고 여러 버전을 유지함으로써 읽기 작업이 쓰기 작업을 차단하지 않도록 하는 동시성 제어 기법**이다.

### 핵심 동작 원리

```text
[트랜잭션 A: 데이터 수정 (UPDATE)]
  └─ 현재 데이터 페이지에 새 버전 기록
  └─ 이전 버전은 별도 공간(Undo Log / Rollback 영역)에 보관

[트랜잭션 B: 일반 조회 (SELECT)]
  └─ 잠금(Lock)을 기다리지 않고, 자신의 시점에 맞는 일관된 스냅샷 버전을 읽음
```

1. **스냅샷 제공 (Consistent Snapshot)**: 트랜잭션이 데이터를 읽을 때 락을 거는 대신, 해당 시점 또는 트랜잭션 시작 기준에 맞는 <strong>일관된 버전(Snapshot)</strong>을 읽는다.
2. **버전 관리 (Undo Log / Rollback 영역)**: 데이터를 수정하거나 삭제할 때 기존 데이터를 곧바로 지우지 않고 별도 공간(Rollback 영역 또는 Undo 로그)에 이전 버전을 남겨두어, 다른 트랜잭션이 필요할 때 과거 버전을 참조할 수 있게 한다.

그리고 이렇게 여러 버전 중 <strong>"어느 시점의 버전을 보여줄 것인가"</strong>를 결정하는 기준이 바로 `READ COMMITTED`, `REPEATABLE READ` 같은 **트랜잭션 격리 수준**과 맞물려 동작한다.

## 3. MVCC의 장점과 단점

| 구분 | 핵심 내용 |
| :--- | :--- |
| **장점** | • **높은 동시성**: 읽기 작업이 쓰기 작업을 막지 않고, 쓰기 작업도 읽기 작업을 막지 않는다.<br>• **잠금 경합 감소**: 일반 읽기 작업에서 락 대기나 데드락 발생 가능성을 크게 줄일 수 있다. |
| **단점** | • **공간 및 정리 오버헤드**: 과거 버전을 유지하고 주기적으로 청소(Purge/Vacuum)하기 위한 추가 저장 공간과 I/O·CPU 비용이 발생한다.<br>• **이상 현상 별도 고려**: 격리 수준이나 구현 방식에 따라 갱신 손실(Lost Update)이나 쓰기 스큐(Write Skew) 같은 동시성 이상 현상을 별도로 제어해야 한다. |

결국 MVCC는 <strong>"저장 공간과 버전 관리 비용을 조금 더 쓰는 대신, 읽기와 쓰기 사이의 잠금 대기를 없애 동시성 성능을 끌어올리는 선택"</strong>으로 정리할 수 있다.
