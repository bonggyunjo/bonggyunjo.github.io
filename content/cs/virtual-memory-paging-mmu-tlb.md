## 1. 가상 메모리(Virtual Memory)와 페이징(Paging)이란?

- **가상 메모리 (Virtual Memory)**: 실제 물리 메모리(RAM)의 용량이 부족할 때 보조기억장치(SSD, HDD 등)의 일부를 RAM처럼 활용하여 실제보다 훨씬 큰 메모리가 있는 것처럼 동작하게 만드는 운영체제(OS)의 메모리 관리 기법이다.
- **페이징 (Paging)**: 가상 메모리 환경에서 프로세스의 논리 주소 공간을 <strong>페이지(Page)</strong>라는 일정한 크기로 자르고, 물리 메모리를 <strong>프레임(Frame)</strong>이라는 동일한 크기로 자른 뒤, 페이지를 물리 메모리의 빈 프레임에 불연속적으로 할당하는 메모리 관리 기법이다.

### 왜 가상 메모리를 만들었을까?

가상 메모리가 없던 초기 환경에서는 여러 프로그램이 물리 RAM 주소를 날것 그대로 직접 공유해서 사용했다.

- 예를 들어 메신저 프로그램이 물리 RAM `100`번지를 쓰고, 게임 프로그램이 `200`번지를 쓰고 있다고 가정해 보자.
- 이때 게임 프로그램에 버그가 발생해 실수로 `100`번지 영역에 데이터를 덮어써 버리면, 아무 죄 없는 메신저 프로그램의 데이터가 망가지며 그 자리에서 강제 종료된다.

이처럼 **프로그램 간 메모리 침범을 막고(격리/보호)**, 물리 RAM 크기의 한계를 넘어 안전하게 메모리를 할당하기 위해 프로세스마다 독립된 가짜 주소 공간인 **가상 메모리**를 부여하게 되었다.

## 2. 주소 변환을 담당하는 핵심 구성 요소

```text
[CPU] ──(가상 주소 요청)──> [MMU (하드웨어 번역기)] ──(물리 주소 변환)──> [물리 RAM]
                                  │
                  ┌───────────────┴───────────────┐
                  ▼                               ▼
       [TLB (초고속 암기 수첩)]        [페이지 테이블 (RAM의 주소록)]
```

1. **페이지(Page)와 프레임(Frame): 4KB 규격 박스**
   - 메모리를 1바이트 단위로 일일이 추적해 관리하는 것은 불가능하므로, OS는 메모리를 **동일한 크기(보통 4KB)로 잘라 관리**한다.
   - 가상 메모리 쪽의 4KB 조각을 **페이지(Page)**, 실제 물리 RAM 쪽의 4KB 빈 공간을 <strong>프레임(Frame)</strong>이라고 부른다.
2. **페이지 테이블 (Page Table)**
   - *"가상 페이지 1번은 실제 물리 RAM 프레임 50번에 들어 있다"*처럼 가상 페이지와 물리 프레임의 매핑 정보를 기록해 둔 주소록이다. **메인 메모리(RAM)에 저장**되어 있다.
3. **MMU (Memory Management Unit)**
   - CPU가 만들어낸 **가상 주소(논리 주소)를 실제 RAM의 물리 주소로 실시간 변환**해 주는 하드웨어 장치다.
   - CPU가 메모리에 접근하려 할 때 중간에서 가로채어 페이지 테이블을 참조한 뒤 실제 물리 주소를 찾아주며, 허가되지 않은 영역 접근을 차단하는 **메모리 보호(Memory Protection)** 역할도 함께 수행한다.
4. **TLB (Translation Lookaside Buffer)**
   - 페이지 테이블은 RAM에 저장되어 있기 때문에, 매번 RAM의 페이지 테이블을 뒤져서 주소를 번역한 뒤 다시 RAM의 실제 데이터에 접근하면 **메모리를 두 번 왕복**해야 하는 속도 저하가 발생한다.
   - 이를 해결하기 위해 MMU 내부에 두는 **초고속 하드웨어 캐시**가 바로 TLB다. 최근에 번역했던 `(가상 페이지 번호 -> 물리 프레임 번호)` 짝을 임시로 기억해 두어, 요청한 주소가 TLB에 있으면(**TLB Hit**) RAM의 페이지 테이블을 거치지 않고 즉시 물리 주소를 얻는다.

## 3. 백엔드 개발자가 가상 메모리를 알아야 하는 이유 (`VIRT` vs `RES`)

리눅스 서버에서 `top`이나 `htop` 명령어로 실행 중인 자바(Spring Boot) 프로세스의 메모리 사용량을 확인하면 다음과 같은 지표를 마주하게 된다.

```text
  PID  USER    VIRT    RES    SHR S  %CPU  %MEM     COMMAND
 1234  spring  8.5g   1.2g  35.2m S   2.5  15.0     java -jar app.jar
```

- **가상 메모리를 모를 때의 오해**: *"우리 서버 물리 RAM이 4GB밖에 없는데, 왜 자바 프로세스가 메모리를 `8.5g(VIRT)`나 잡아먹고 있지? 메모리 누수인가?"* 하고 당황하게 된다.
- **가상 메모리를 알 때의 정확한 진단**: `VIRT`는 OS가 프로세스에 할당해 준 가짜 가상 주소 공간의 총합(예약분·공유 라이브러리 매핑 포함)일 뿐이다. 실제로 물리 RAM 프레임을 점유하고 있는 <strong>진짜 메모리 사용량은 `RES(1.2GB)`</strong>이므로, 서버 메모리는 매우 여유롭고 정상 상태임을 정확히 판단할 수 있다.

## 4. 가상 주소가 물리 주소로 변환되는 과정

CPU가 만들어낸 가상 주소(논리 주소)는 두 부분으로 나뉜다.

> **가상 주소 = `[ 페이지 번호 (p, Page Number) ]` + `[ 오프셋 (d, Page Offset) ]`**

- **페이지 번호 (`p`)**: 데이터가 몇 번째 페이지에 속해 있는지를 나타내는 번호 (주소 변환의 대상)
- **페이지 오프셋 (`d`)**: 해당 페이지 시작점으로부터 얼마나 떨어져 있는지를 나타내는 상대 거리 (변환 후에도 **그대로 유지**)

### 단계별 주소 변환 흐름

1. **가상 주소 전달**: CPU가 가상 주소 `(p, d)`를 MMU로 보낸다.
2. **TLB 조회 (빠른 경로 확인)**: MMU가 내부의 초고속 캐시인 TLB에서 페이지 번호 `p`가 있는지 먼저 찾는다.
   - **TLB Hit (캐시에 있는 경우)**: TLB에서 `p`에 대응하는 실제 <strong>프레임 번호 `f`</strong>를 즉시 꺼낸다.
   - **TLB Miss (캐시에 없는 경우)**: RAM에 있는 **페이지 테이블**로 가서 `p`번째 항목을 조회해 프레임 번호 `f`를 찾아온 뒤, 다음 요청을 위해 TLB에 새로 등록한다.
3. **물리 주소 완성**: 찾아낸 프레임 번호 `f`와 원래 가지고 있던 오프셋 `d`를 그대로 합쳐 최종 물리 주소 `(f, d)`를 만든다.
4. **메모리 접근**: 완성된 물리 주소 `(f, d)`로 실제 RAM에서 데이터를 읽거나 쓴다.

### 예시 1: 숫자로 계산해 보기

페이지 크기가 **100**이고, CPU가 가상 주소 **235**번지에 접근하려는 상황을 가정해 보자.

1. **주소 분리**: `235`를 페이지 크기 `100`으로 나누면 몫인 **페이지 번호(`p`)는 2**, 나머지인 **오프셋(`d`)은 35**가 된다. (2번 페이지의 35번째 칸)
2. **프레임 찾기**: MMU가 TLB 또는 페이지 테이블을 조회해 *"2번 페이지는 실제 물리 메모리의 **7번 프레임**에 있다"*는 매핑을 찾는다.
3. **물리 주소 결합**: 7번 프레임의 시작 주소(`700`번지)에 원래 오프셋 `35`를 그대로 더하면, 최종 물리 주소는 **735번지**가 된다.

### 예시 2: 아파트 동·호수 비유

CPU가 <strong>"가상 3동 102호에 있는 데이터를 가져와 달라"</strong>고 요청한 상황이다.

1. **TLB 먼저 확인**: MMU가 암기 수첩(TLB)을 펼쳐 *"가상 3동 = 진짜 물리 88동"*이라는 기록을 발견한다. (**TLB Hit** — 단 1클럭 만에 번역 완료)
2. **만약 수첩에 없다면 (TLB Miss)**: MMU가 RAM의 거대한 페이지 테이블을 뒤져 *"가상 3동은 진짜 88동"*임을 확인한 뒤, 다음을 위해 TLB에 메모해 둔다.
3. **최종 변환**: <strong>동(페이지 번호)</strong>만 `3동`에서 `88동`으로 바뀌고, <strong>호수(`102호`, Offset)</strong>는 그대로 유지되어 최종적으로 **물리 RAM 88동 102호**에서 데이터를 꺼내온다.

## 5. 핵심 요약

- **가상 메모리**: 프로세스 간 메모리 영역을 격리해 보호하고, 물리 RAM보다 큰 메모리 공간을 쓸 수 있게 해주는 OS의 메모리 관리 추상화다.
- **페이지 vs 프레임**: OS가 메모리를 관리하기 위해 자른 4KB 규격 단위로, 가상 메모리 조각은 **Page**, 물리 RAM의 빈 슬롯은 **Frame**이라 부른다.
- **MMU & TLB**: **MMU**가 페이지 테이블을 참조해 가상 주소를 물리 주소로 실시간 변환하며, RAM 왕복 오버헤드를 줄이기 위해 **TLB**가 최근 변환된 매핑 정보를 초고속으로 캐싱한다.
