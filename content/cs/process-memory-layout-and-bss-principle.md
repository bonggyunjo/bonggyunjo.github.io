## 1. 왜 프로세스 메모리를 4개의 영역으로 나눌까?

운영체제(OS)는 디스크에 있던 프로그램이 실행되어 프로세스(Process)가 되면 독립적인 가상 메모리 공간을 할당한다.

현대 컴퓨터는 프로그램의 명령어와 데이터를 모두 같은 메인 메모리에 올려놓고 실행하는데, 이를 섞어 쓰지 않고 다음 **세 가지 기준**으로 나누면서 **Code, Data, Heap, Stack** 4대 영역이 만들어진다.

1. **명령어인가, 데이터인가? (➔ Code 분리)**
   실행 중인 프로그램 코드가 버그나 외부 공격으로 덮어씌워지면 시스템이 즉시 붕괴한다. 그래서 변하면 안 되는 기계어 명령어만 따로 모아 **읽기·실행 전용(Read/Execute)** 권한으로 보호한다.
2. **수명이 영구적인가, 임시적인가? (➔ Data 분리)**
   남은 데이터 중 프로그램 시작부터 종료까지 계속 살아 있고 크기도 변하지 않는 데이터(전역·정적 변수)를 **Data**로 묶는다. 컴파일 시점에 주소와 크기가 확정되므로 실행 중 별도의 할당·해제 비용이 들지 않는다.
3. **실행 중 생기는 데이터의 수명이 규칙적인가? (➔ Stack vs Heap)**
   함수 호출 순서에 맞춰 규칙적으로 생겼다가 사라지는 데이터는 **Stack**으로, 수명과 크기를 예측할 수 없는 동적 데이터는 **Heap**으로 나뉜다.

```text
낮은 주소 (0x0000...)
┌──────────────────────────────┐
│          Code 영역           │  기계어 명령어 (Read / Execute 전용)
├──────────────────────────────┤
│      Data 영역 (초기화)      │  초기값이 있는 전역·정적 변수
├──────────────────────────────┤
│      BSS 영역 (미초기화)     │  초기값 없는(0) 전역·정적 변수
├──────────────────────────────┤
│          Heap 영역           │  동적 할당 (낮은 주소 ➔ 높은 주소)
│              ↓               │
│          (빈 공간)           │
│              ↑               │
│          Stack 영역          │  지역 변수, 매개변수 (높은 주소 ➔ 낮은 주소)
└──────────────────────────────┘
높은 주소 (0xFFFF...)
```

| 영역 | 저장 대상 | 생명주기 | 핵심 특징 |
| :--- | :--- | :--- | :--- |
| **Code** | 컴파일된 기계어 명령어 | 시작 ~ 종료 | **읽기 전용** 보호 (임의 수정 시 오류) |
| **Data / BSS** | 전역 변수, 정적(`static`) 변수 | 시작 ~ 종료 | 초기화 여부에 따라 Data / BSS로 구분 |
| **Heap** | 동적 할당 객체 (`malloc`, `new`) | 할당 ~ 해제(또는 GC) | 낮은 주소 ➔ 높은 주소, 크기가 유동적 |
| **Stack** | 지역 변수, 매개변수, 복귀 주소 | 함수 호출 ~ 반환 | 높은 주소 ➔ 낮은 주소, LIFO 구조 |

## 2. 영역별 상세 동작과 BSS의 디스크 절약 원리

### 1) Code 영역
작성한 소스 코드가 컴파일되어 변환된 **기계어 명령어**가 저장된다. CPU는 이 영역에서 명령어를 하나씩 읽어와(Fetch) 실행하며, 실행 중 코드가 변조되는 것을 막기 위해 읽기 전용 권한이 적용된다.

### 2) Data 영역과 BSS 영역
전역 변수(Global)와 정적 변수(Static)는 함수가 끝나도 사라지지 않고 프로그램이 종료될 때까지 유지되므로 Data 영역에 자리 잡는다. 실제 실행 파일과 메모리에서는 초기화 여부에 따라 두 구역으로 나뉜다.

- **Data (Initialized Data)**: 초기값이 지정된 전역·정적 변수 (`int a = 10;`)
- **BSS (Block Started by Symbol)**: 초기값이 없거나 `0`으로 초기화된 전역·정적 변수 (`int b;`)

#### BSS 영역은 어떻게 용량을 아낄까?
핵심은 <strong>BSS가 일차적으로 절약하는 대상이 실행 중인 RAM이 아니라 '디스크 공간(실행 파일 크기)'</strong>이라는 점이다.

> *"어차피 전부 `0`으로 채울 데이터라면, 실행 파일 안에 `0`을 일일이 저장하지 않고 크기(숫자)만 적어두자."*

예를 들어 약 **4MB** 크기의 전역 배열을 선언한 두 경우를 비교하면 차이가 명확하다.

| 구분 | 코드 예시 | 실행 파일(`.exe`, `ELF`) 저장 방식 | 실행 파일 크기 영향 |
| :--- | :--- | :--- | :--- |
| **Data 영역** | `int arr[1000000] = {1, 2, 3, ...};` | 초기값이 제각각이므로 **4MB 데이터를 통째로 기록** | 파일 크기 **+4MB 증가** |
| **BSS 영역** | `int arr[1000000];` (또는 `= {0};`) | 헤더에 **"시작 주소 X, 크기 4MB" 메타데이터만 기록** | **단 몇 바이트**만 사용 |

이후 프로그램이 실행되는 시점에 OS가 BSS 메타데이터를 보고 RAM에 4MB 공간을 잡은 뒤 한꺼번에 `0`으로 초기화해 준다.

### 3) Heap 영역
런타임에 개발자나 애플리케이션의 필요에 따라 **동적으로 할당하는 데이터**가 저장된다. **낮은 주소에서 높은 주소 방향**으로 커지며, C/C++에서는 `free`/`delete`로 직접 해제하고 Java·JavaScript·Python에서는 가비지 컬렉터(GC)가 사용하지 않는 객체를 회수한다.

### 4) Stack 영역
함수 호출과 관련된 **지역 변수, 매개변수, 복귀 주소** 등이 **스택 프레임(Stack Frame)** 단위로 저장된다. **후입선출(LIFO)** 구조로 **높은 주소에서 낮은 주소 방향**으로 자라며, 함수가 호출되면 쌓이고(Push) 반환되면 즉시 제거(Pop)된다.

## 3. Heap과 Stack은 왜 이렇게 설계되었을까?

### 왜 서로 마주 보고 자랄까?
프로세스에 주어진 가상 메모리 크기는 한정되어 있다. 어떤 프로그램은 Heap을 많이 쓰고, 어떤 프로그램은 함수 호출이 깊어 Stack을 많이 쓴다. 두 영역을 양 끝에 두고 **서로 마주 보며 자라게 하면 중간의 빈 공간을 유연하게 공유**할 수 있어 메모리 낭비를 줄일 수 있다. (물론 두 영역이 서로의 경계를 넘으면 오버플로우가 발생한다.)

### 왜 Stack이 Heap보다 훨씬 빠를까?
- **Stack**: 스택 포인터(SP) 주소값만 더하거나 빼는 CPU 명령어 한 번으로 할당과 해제가 끝난다. 메모리도 연속적이라 CPU 캐시 적중률이 높다.
- **Heap**: 할당할 때마다 적절한 크기의 빈 메모리 블록을 찾아야 하고, 해제할 때도 포인터 추적이나 GC 오버헤드가 뒤따른다.

## 4. 대표적인 메모리 오류와 이 구조를 알아야 하는 이유

### 대표적인 메모리 오류 2가지
- **Stack Overflow**: 종료 조건 없는 재귀 함수를 호출하거나 너무 큰 지역 변수를 선언해 Stack 한계를 초과할 때 발생한다.
- **Memory Leak (메모리 누수)**: Heap에 동적 할당한 메모리를 다 쓰고도 해제하지 않거나(또는 참조를 계속 물고 있어 GC가 회수하지 못해) 가용 메모리가 점차 고갈되는 현상이다.

### 결국 바닥 구조를 알아야 하는 이유
C 같은 저수준 언어부터 Java, Python 같은 고수준 언어까지 모두 이 **4대 영역** 위에서 동작한다.

- 자바에서 <strong>원시 타입(Primitive)</strong>과 <strong>참조 타입(Reference)</strong>이 왜 다르게 저장·동작하는지,
- <strong>가비지 컬렉터(GC)</strong>가 왜 Stack이 아니라 Heap 영역만 청소하는지,
- 장애 상황에서 `StackOverflowError`와 `OutOfMemoryError`를 어떻게 구분해 추적해야 하는지

결국 메모리 구조에 대한 이해가 장애 대응과 성능 최적화의 출발점이 된다.
